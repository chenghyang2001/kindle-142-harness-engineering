# ch11｜全書總複習：Capstone 修補代理群與上線前檢查

## 這章在講什麼

- 前十章各講一道控制；真正的系統要把它們串起來。作者的期末專題是一個「自動資安修補代理群」：分流代理讀外部漏洞回報、修補代理在沙盒寫修正、部署代理把核准的修正推上正式環境。
- 六道必要閘門：綁受眾的憑證（分流代理的憑證不能拿去部署）、上下文隔離（回報裡的注入要先清掉才交給修補代理）、意圖合約（修補只能動相關檔案，碰到驗證或計費檔立刻警示）、記憶帳本（成功的修補摘要提升進記憶、失敗實驗打墓碑）、人類核准閘門（部署要明確的核准憑證）、可驗證的稽核信封（回報、diff、測試、部署收據的雜湊）。
- 上線前的五道檢查：身分與委派、意圖與目的、上下文與隔離、狀態與回滾、治理與證據。

## 作者做過的實驗／例子

- HarnessLab 的 `capstone/remediation_fleet.py` 是可執行的參考實作，附單元測試；`harnesslab verify` 一次驗十章實驗、五個安全不變量與 capstone，最後輸出一個防竄改的完成收據雜湊。
- 作者把這五道檢查稱為「給代理群正式自主權之前」必須通過的客觀門檻。

## 演練

> 說明：練習視窗工作目錄是 practice/。指令：`(cd HarnessLab && PYTHONUTF8=1 python -m harnesslab.cli capstone --json)`、`(cd HarnessLab && PYTHONUTF8=1 python -m unittest discover -s capstone -p "test_*.py")`、`(cd HarnessLab && PYTHONUTF8=1 python -m harnesslab.cli verify)`。不要修改 HarnessLab/ 原始碼。

### 練習 1：Capstone 六道閘門對照全書十章

**目的**：把一個完整的多代理系統拆回十章的控制，確認自己串得起來。
**送給練習視窗的提示詞**：

```text
執行 capstone（--json 存到 ch11/capstone.json）與 capstone 單元測試（輸出存到 ch11/capstone-test.txt），再讀 HarnessLab/capstone/remediation_fleet.py。
寫出 ch11/capstone-map.md：
1. 一張表：六道閘門、在 remediation_fleet.py 裡對應的方法或程式段落（寫出名稱）、capstone.json 裡的證據欄位與實際值、對應全書第幾章。
2. 三個代理（分流、修補、部署）各拿到什麼身分與權限，彼此之間怎麼交接。
3. 單元測試涵蓋了哪些閘門、哪一道沒有被測試涵蓋（照實寫）。
4. 你認為這個參考實作離正式上線還差哪三件事？（例如核准憑證怎麼簽、隔離只靠關鍵字等）
```

**觀察重點**：

- 對照表的方法名稱是否真的存在於程式碼中？
- 是否誠實指出測試沒涵蓋的閘門？
- 「離正式上線還差什麼」是否具體，且能連回各章練習中發現的弱點（關鍵字偵測、期限沒人檢查等）？

### 練習 2：用 verify 收尾，替自己的代理系統做上線檢查

**目的**：把全書收斂成一份可以帶回工作現場的檢查表。
**送給練習視窗的提示詞**：

```text
執行 (cd HarnessLab && PYTHONUTF8=1 python -m harnesslab.cli verify) > ch11/verify.txt，記下完成收據雜湊。
接著讀 ch01～ch10 底下你之前練習產出的 .md 檔（有就讀、沒有就略過並註明），寫出 ch11/readiness.md：
1. 假設一個虛構的系統「電商客服退款代理群」（自己定義 3 個代理與它們的工具），依 WORKBOOK.md 第 5 節的五道檢查（身分與委派、意圖與目的、上下文與隔離、狀態與回滾、治理與證據），每道寫出：這個系統要做什麼、對應哪一章、用什麼證據證明有做到。
2. 「本次演練中真實子代理的表現」小節：從前面各章用到 claude -p 的練習結果中，挑出 3 個模型主動越界或被誘導的實例，以及 2 個模型自己拒絕越界的實例（找不到就照實寫找不到），說明 harness 為什麼仍然不能依賴模型自律。
3. 一句話總結：本書最重要的一個觀念。
```

**觀察重點**：

- verify 是否全部通過、收據雜湊是否有記錄？
- 五道檢查是否每道都有「證據」而不只是「要做什麼」？
- 是否真的引用了前面練習的實際結果，而不是重新編造？

## 教練解說要點

- 全書可以收斂成一句：模型負責提議，harness 負責授權、記錄與收拾。
- 十道控制單獨看都不複雜，難的是在長時程與多代理的情境裡一起運作，而且每一道都留下證據。
- 演練中真實子代理有時守規矩、有時被帶偏；正因為結果不穩定，控制才必須放在模型外面。
